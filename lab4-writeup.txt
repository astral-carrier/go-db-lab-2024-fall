My choice of deadlock detection was to use a directed graph of dependencies, like was recommended.
The dependency graph is global across the buffer pool because dependencies can span across pages. When a shared lock
is denied to a transaction A, A is set in the graph to depend on the transaction currently holding the
exclusive lock (as that is the only transaction blocking A from getting the shared lock). If A is denied an exclusive
lock, it is set to depend on all the transactions holding the shared lock as well as the one holding the exclusive lock,
as all of these transactions are blocking A from getting the exclusive lock. When transactions commit or abort, they
release all their locks and delete themselves from the dependency graph.
Because transactions constantly try and retry to acquire locks, the dependency graph is quite up to date.

I made no changes to the API.
